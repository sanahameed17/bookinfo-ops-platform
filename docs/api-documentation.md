# API documentation

Interactive OpenAPI documentation (generated by FastAPI from the Pydantic models): **http://127.0.0.1:8000/docs**
(raw schema: `/openapi.json`).

Conventions: JSON only; CPU in **cores**; memory in **MiB**; timestamps in **UTC ISO 8601**; unknown values are
`null` (never 0). Every endpoint is read-only except `POST /api/chat`, which changes nothing in the cluster either.

## Error format

```json
{"error": {"code": "PROMETHEUS_UNAVAILABLE", "message": "Cannot reach Prometheus at http://127.0.0.1:9091. Is the port-forward running?", "details": {"url": "http://127.0.0.1:9091"}}}
```

| HTTP | code | When |
|---|---|---|
| 404 | `SERVICE_NOT_FOUND` | unknown service name (`details.available_services` lists the valid ones) |
| 422 | `VALIDATION_ERROR`, `INVALID_RANGE` | bad path/body, or `minutes` not 5, 15 or 60 |
| 502 | `PROMETHEUS_QUERY_ERROR` | Prometheus answered with an error or invalid data |
| 502 | `LLM_API_ERROR` | the LLM provider failed (key, quota, model, network) |
| 503 | `KUBERNETES_UNAVAILABLE` | kubeconfig/context problem or the API server is unreachable |
| 503 | `PROMETHEUS_UNAVAILABLE` | Prometheus is unreachable or timed out (only for metric-history endpoints; other endpoints still answer and mark metrics as unavailable) |
| 503 | `LLM_NOT_CONFIGURED` | no `LLM_API_KEY` |
| 500 | `INTERNAL_ERROR` | unexpected error (logged) |

## Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/api/health` | Backend, Kubernetes (context, server, version) and Prometheus (version) connectivity; always HTTP 200 |
| GET | `/api/config` | Non-secret runtime settings (namespace, URLs, thresholds, LLM model, whether a key is set) |
| GET | `/api/status` | Deterministic status: `normal` / `anomalous` / `prometheus_unavailable` / `metrics_unavailable`, with anomalies (pod, metric, value, threshold) and missing metrics |
| GET | `/api/cluster/overview` | Totals: microservices, deployments, pods, running, unhealthy, restarts, CPU, memory, % of cluster capacity, Chaos Mesh warnings |
| GET | `/api/pods` | Every pod in the namespace with service, deployment, version, containers and CPU/memory |
| GET | `/api/events` | Namespace events, newest first |
| GET | `/api/dependencies` | Service call graph from Istio telemetry or Jaeger (`available:false` + `note` if neither has data) |
| GET | `/api/services` | Service cards (inventory) |
| GET | `/api/services/{service_name}` | Full detail page data |
| GET | `/api/services/{service_name}/workloads` | Deployments (versions) and ReplicaSets |
| GET | `/api/services/{service_name}/pods` | Pods of the service with metrics |
| GET | `/api/services/{service_name}/metrics/cpu?minutes=15&by=pod` | CPU history; `by=container` for per-container series |
| GET | `/api/services/{service_name}/metrics/memory?minutes=15&by=pod` | Memory history |
| GET | `/api/services/{service_name}/events` | Events of the service, its Deployments, ReplicaSets and Pods |
| GET | `/api/metrics/cpu?minutes=15` | CPU history of every pod in the namespace |
| GET | `/api/metrics/memory?minutes=15` | Memory history of every pod |
| GET | `/api/metrics/restarts` | Restarts from kube-state-metrics **and** from the Kubernetes API |
| POST | `/api/chat` | Ask the AI OpsAgent |

## Examples

### GET /api/services (shortened)
```json
{
  "meta": {"namespace": "bookinfo", "generated_at": "2026-11-23T13:00:00Z", "kubernetes_context": "docker-desktop",
           "prometheus_available": true, "prometheus_error": null},
  "services": [{
    "name": "reviews", "health": "Healthy", "health_reason": "3/3 pods ready", "status": "normal",
    "ready_replicas": 3, "desired_replicas": 3, "pod_count": 3, "ready_pods": 3,
    "versions": ["v1", "v2", "v3"], "version_count": 3,
    "deployments": ["reviews-v1", "reviews-v2", "reviews-v3"],
    "cpu_cores": 0.03, "memory_mib": 450.0, "metrics_state": "ok", "restart_count": 9,
    "anomalies": [], "updated_at": "2026-11-23T13:00:00Z"
  }]
}
```

### GET /api/services/reviews (top-level keys)
`meta`, `summary` (card), `service` (name, namespace, type, cluster_ip, selector, ports, created_at),
`deployments[]` (version, replicas, images, replicasets, pods), `replicasets[]`,
`pods[]` (phase, ready, pod_ip, node_name, containers[] with image, state, restarts, requests, limits,
readiness/liveness probe, cpu_cores, memory_mib), `metrics` (availability + PromQL used),
`diagnostics` (status, failed/pending, CrashLoopBackOff, ImagePullBackOff, not ready, warning events,
resources_configured), `istio` (virtual_services with route weights, destination_rules with subsets, gateways),
`dependencies` (available, source, calls, called_by, note), `events[]`.

```json
             "points": [{"t": "2026-11-23T12:55:00Z", "v": 0.0105}, {"t": "2026-11-23T12:55:15Z", "v": null}]}]}
```

### POST /api/chat
Request:
```json
{"message": "Compare CPU utilization of reviews-v1 and reviews-v3.", "history": []}
```
Response:
```json
{"answer": "reviews-v1 uses 0.0094 cores and reviews-v3 0.0096 cores - practically the same, both far below the 0.1-core threshold.",
 "tools_used": [{"tool": "get_pod_cpu_usage", "input": {"service": "reviews"},
                 "output_preview": "{\"unit\": \"cores ...\", \"pods_sorted_highest_first\": [...]}", "duration_ms": 41}],
 "model": "deepseek-chat", "duration_ms": 8123, "generated_at": "2026-11-23T13:00:08Z"}
```
(The numbers above are only an example of the format. Real answers come from your cluster.)

## PowerShell examples

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health | ConvertTo-Json -Depth 5
(Invoke-RestMethod http://127.0.0.1:8000/api/services).services | Format-Table name, health, status, cpu_cores, memory_mib
Invoke-RestMethod http://127.0.0.1:8000/api/chat -Method Post -ContentType 'application/json' `
  -Body '{"message": "Are any Pods unhealthy?"}'
```
